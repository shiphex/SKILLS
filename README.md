# SKILLS 技能备份仓库

本仓库用于备份我在各项目开发过程中使用过的技能。其中部分来自网络，部分在网络已有技能的基础上进行了改进，部分由我自行编写。具体来源、修改情况和作者信息以各技能保留的原始说明及仓库索引为准。

技能可能来自 Codex、Claude Code、Pi Agent 等开发环境。仓库用于保存和查找技能，不包含采集工具。当前尚未导入技能。

## 目录结构

```text
SKILLS/
├── README.md       # 用途、备份与恢复说明
├── AGENTS.md       # 贡献与 Agent 操作指南
├── CATALOG.md      # 技能索引与来源记录
├── .gitignore
├── .gitattributes
└── skills/
    └── .gitkeep    # 空目录占位，首个技能导入后移除
```

每个技能完整保存于 `skills/<技能标识>/`，例如 `skills/example-skill/SKILL.md`。此路径仅为结构示例。保留技能自带脚本、参考资料、资源和许可证，不调整其内部目录。每个技能只保存一个选定版本，不使用版本编号目录。

## 备份流程

1. 提供存放各项目的根目录，由 Agent 逐项目检查技能位置与配套文件，不假定不同工具采用相同布局。
2. 检查完整技能包，与已有技能比较相对文件路径和字节内容；敏感文件或无法确认的包边界应先报告。
3. 无冲突时复制整个技能包至 `skills/`，不移动或修改源文件。完全一致的技能只保留一份，并补充所有项目来源。
4. 在 [CATALOG.md](CATALOG.md) 记录项目标识、项目内相对路径、Agent 类型、备份日期、创作来源类别及已有作者、链接和授权信息。
5. 核对复制结果与索引，再提交 Git。首个技能导入后移除 `skills/.gitkeep`。

创作来源类别为“网络获取”“基于网络改进”“自行编写”；无法确认时标记“待确认”。使用过技能的项目与技能的原始创作来源分别记录。项目路径采用项目标识加项目内相对路径，不记录个人机器绝对路径。

## 差异与同名处理

相同技能存在任何内容差异时，暂停该技能归档，展示各来源的差异摘要和建议，由我决定保留哪个版本，或进行优化合并。其他无冲突技能可以继续备份。

选择合并后，先呈现具体方案，经我确认后执行并验证，在索引记录各来源和合并说明。不得自动覆盖或依据修改时间选择版本。未解决的冲突列入交付报告，不作为已完成备份。

同名但用途不同的技能独立保存，使用项目名称后缀区分，例如 `example-skill-project-a`；此名称仅为示例。

## 恢复与检查

从索引找到归档目录，将完整技能包复制到目标项目所用 Agent 的技能目录，按技能原有说明安装依赖。恢复位置取决于目标工具和项目配置。目标已有同名技能时先比较，由我决定替换或合并，不直接覆盖。

在仓库根目录执行以下 PowerShell 命令检查改动：

```powershell
Get-ChildItem -Force
git status --short
git diff --check
git diff --cached --check
```

仓库没有统一构建命令或测试框架。复制时核对完整文件清单及字节内容；涉及脚本合并时，使用技能原有环境验证行为。贡献规则见 [AGENTS.md](AGENTS.md)。

## 署名与授权

保留各技能原有作者署名、来源链接、许可证和修改说明。本仓库不将全部技能声明为原创，也不为它们统一授予许可证；使用或转发时应查看具体技能的授权信息，缺失时不推断授权。
